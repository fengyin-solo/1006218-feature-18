# 水电站机组运行检修管理平台

面向电站台账、机组运行、调速励磁、主变与闸门、大坝渗流位移监测、机组检修与发电计划的一体化水电站运行检修管理平台。

这是一个**纯前端**管理平台：Vue 3 + Vite + TypeScript，仓库里没有后端服务。业务数据由
`frontend/src/data/` 下的本地数据层提供：首次打开用示例数据播种，之后的登记、筛选与状态流转
结果都持久化在浏览器 `localStorage` 里，刷新或重开浏览器都还在。dev server 已关掉自动打开页面，
启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 Vue 3 + Vite + TypeScript 前端（唯一运行单元）
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/local-service.ts   本地数据服务：列表、筛选、动作流转、导出
│   ├── src/data/             模块元数据 / 示例数据 / localStorage 持久化
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false，无 /api 代理）
├── .gitignore
└── docker-compose.yml
```

## 启动

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，需要自己访问。

生产构建：

```bash
cd frontend
npm run build
```

## 汛期水情空值处理（hydrology / flood / patrol）

针对「取不到数被随手填 0，事后分不清真零还是缺数」的问题，水情链路按以下规则落地：

### 空值语义

- 上游水位、下游水位、入库流量、出库流量四个遥测项取不到数时一律留空（`null`），**绝不写 0**；
  真实为零（如关闸时出库流量 0）仍以数字 `0` 保存，与空值严格区分。
- 页面上空值单元格显示「暂无数据（取数失败原因）」，取数面板提供单项「重试取数」；
  空值记录在水情页面单独成表，不混进实数表格，也不进今日流量平均值统计。
- 导出 CSV 与页面同口径：实数、空值都导出，空值单元格导出为「暂无数据（原因）」，不会导出成 0。

### 观测、中断与补测

- 观测时段按观测时间整点归槽；**同一时段重复上报只保留最后一次**（按观测时间覆盖原记录，不新增行）。
- 提交带幂等键：网络重试时若上一次已落库，直接返回原记录，不重复登记。
- 遥测**连续中断超过 60 分钟，自动取数提交一律锁定**，提示先人工补测；补测值标记为「人工补测」，
  补到哪项就把哪项从缺测清单摘掉，仍缺的项继续留空并保留原因，补测后才允许走调度。

### 流量平衡与兜底

- **空值不参与流量平衡校验**：入库或出库缺测时该时段跳过校验并明示，绝不拿 0 或兜底值冒充。
- 两项齐全时按 `|入库-出库| ≤ 5% × 入库` 判断平衡。
- 上游水位、入库流量缺失时，调度建议沿观测序列向前取最近一个非空值**兜底**；建议文案和落库值都
  标注「兜底」及来源时段、来源记录编号。找不到任何前时段值时不允许下达调度，必须先补测。

### 复核回写与对账

- 复核结论回写到**泄洪操作的调度待办**（`floodTodos`）：待办明细由水情记录派生，
  水情页面「待调度记录」与泄洪页面「待调度待办」读同一份数据，两处条数始终一致，对账栏实时校验。
- 复核的处理结论同时回写**现场巡视隐患清单**（patrol）：有缺测/不平衡自动开一条「水情回写」隐患，
  无遗留则关闭旧隐患。隐患清单页面条数与导出 CSV 条数相同。
- 现场登记隐患时，同业务日期 + 同巡视点位 + 同描述的重复上报**只认第一次取值**，
  后到的按重复处理、不计入清单不导出，仅在「重复上报记录」里留痕。

### 环节顺序

- 链路固定为 待观测 → 已观测 → 已调度 → 已复核；通用模块同理按 `modules.ts` 的状态链推进。
- **跳级操作直接拦下**，并明确提示缺哪一步（如「当前为待观测，请先走下达调度」）。

### 存量迁移（v1 → v2，顺序固定不可跳步）

老版本浏览器里的扁平存储首次打开 v2 时自动迁移一次，迁移报告写入
`hydropower-plant-om:migration-report`，顺序如下：

1. **升级存储壳到 v2**：加版本号，补齐调度待办、隐患、取数元数据容器；这一步没完成，后面不执行。
2. **水情记录按观测时间升序回填**，逐条套用「随手填零」识别规则：
   - 上游/下游水位 `=== 0`：水位物理不可能为 0，一律判缺数 → 留空（null），记录原因待补测；
   - 入库流量 `=== 0`：仅当其前、后相邻时段入库流量都非零（孤立零点）才判缺数；连续 0 保留为真零；
   - 出库流量 `=== 0`：仅当相邻时段都非 0（孤立零）且同期入库非零时判缺数；
     相邻任一为 0 视为连续关闸，保留为真实零；
   - 值无法解析为数值（占位文本等）的，一律判缺数。
   - 判缺数的项不凭空补造数值，写 null + 迁移原因，状态回到「待观测」等待补测；保留的 0 按实数参与统计。
3. **现场巡视隐患按业务日期升序补数**：空缺/无法解析的登记字段不填默认值，进每条记录的
   「缺失字段」单独罗列（页面与导出都有该列）。
4. **重建派生表并对账**：调度待办由已复核水情记录重新推导，待调度条数两处立即对齐。

想重新走迁移：清掉 `hydropower-plant-om:entries` 后再用 v1 结构的数据访问即可；
水情/巡视页面也提供「重置示例数据」回到 v2 播种状态。

## 约定

- 每个模块的页面在 `frontend/src/views/<模块>/index.vue`，页面只负责渲染，读写统一走
  `frontend/src/api/local-service.ts`。
- 字段、状态、动作与流转目标集中在 `frontend/src/data/modules.ts`；示例数据在
  `frontend/src/data/seed.ts`。
- 状态流转只允许在 `local-service.ts` 里改，页面组件不做业务判断。
- 想回到初始数据：清掉浏览器里 `hydropower-plant-om:entries` 这一项，或调用 `resetModule(模块)`。
